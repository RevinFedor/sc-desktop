# Knowledge: интерактивные субтитры YouTube

SC Browser Parser заменяет визуальный слой субтитров YouTube собственным
интерактивным слоем только после нажатия штатной кнопки **CC**. Родная дорожка
остаётся источником текста и таймкодов; расширение не распознаёт аудио и не
запускает платный AI, пока у видео есть субтитры.

## Пользовательский контракт

- CC включена → поверх плеера показывается текущая реплика.
- Наведение на реплику → появляется перевод Azure Translator.
- Клик по слову → карточка с вариантами перевода, частью речи и примерами из
  текущего видео.
- Английская строка остаётся над русской; сохранённые слова постоянно отмечены
  в обеих строках, а не только пока открыт popover.
- Слева: предыдущая реплика, повтор, следующая реплика.
- Справа: поменять стороны управления, автопауза, настройки и drag-handle для
  сохранённого X/Y-смещения субтитров.
- Сохранение слова/фразы сначала пишет offline-копию расширения, затем
  синхронизирует её с общим словарём Voice Record; вход в сторонний аккаунт
  Language Reactor не нужен.
- Старый Language Reactor может оставаться установленным на время миграции. Его
  субтитры, уведомления и большая боковая панель скрываются только после того,
  как SC успешно получил собственные реплики. При ошибке старый слой не
  скрывается — существующая возможность не теряется.

## Azure Translator

Ресурс:

- регион: `northeurope`;
- Text Translation endpoint: `https://api.cognitive.microsofttranslator.com`;
- тариф: `Free F0`;
- ключ хранится только локально в
  `~/.config/sc/settings.json → api_keys.AZURE_TRANSLATOR_KEY`;
- значение ключа запрещено записывать в Git, Markdown, логи, extension storage
  или ответы localhost API.

Расширение не получает Azure key. Оно вызывает loopback-мост SC Desktop:

```text
YouTube content-script
  → http://127.0.0.1:53127/translator/*
  → Electron читает локальный ключ
  → Azure Translator
  → ответ без credentials возвращается расширению
```

Маршруты:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/translator/status` | Наличие конфигурации без выдачи ключа |
| POST | `/translator/translate` | Перевод одной или нескольких реплик |
| POST | `/translator/dictionary` | Варианты перевода слова, части речи и back-translations |
| POST | `/yt-learning-cues` | Бесплатная локальная дорожка с таймкодами |
| POST | `/learning/explain` | Короткое контекстное объяснение слова через Voice Record |
| POST | `/learning/selection` | Передать выбранное слово/фразу в Option+Space Voice Record |
| POST | `/learning/practice` | Ограниченный двуязычный turn разговорной практики |
| POST | `/vocabulary/sync` | Двусторонняя синхронизация offline-словаря и review-outbox |
| GET/POST | `/learning/entry` | Legacy-записи `library.db`, читаются однократной миграцией |

В режиме «При наведении» Azure вызывается только для наведённой реплики. В
режиме «Всегда» заранее переводится небольшое окно вокруг текущей позиции, а не
всё видео. Повторные тексты читаются из `translation_cache`, поэтому не расходуют
квоту снова.

## Получение дорожки

Основной путь читает выбранный caption track из main-world YouTube player и
пытается получить `json3`/VTT. В текущей версии YouTube встречается состояние,
где `captionTracks[].baseUrl` валиден для самого плеера, но script-fetch получает
HTTP 200 с пустым body.

В этом случае расширение вызывает `/yt-learning-cues`. Electron использует уже
существующий бесплатный race:

```text
youtube-transcript-api × yt-dlp
  → первый непустой результат
  → файл *__timestamps.txt
  → cues [{startMs, endMs, text}]
```

Файл с таймкодами кэшируется рядом с обычным транскриптом. Повторное открытие
видео не запускает worker заново.

## Интерактивный текст и выбор фразы

Токенизация следует пользовательскому понятию слова. Дефис без пробелов
соединяет части в один кликабельный объект (`short-term`,
`state-of-the-art`); тире с пробелами оставляет два слова. Та же сегментация
используется в примерах, alignment и выборе фразы, поэтому клик и сохранение не
расходятся между экранами.

Выбор фразы начинается Shift-кликом/Shift над словом либо быстрым повторным
кликом. В этом режиме A/D сохраняют anchor и переходят по соседним репликам,
а не двигают границу на одно слово. Наведение в новой реплике показывает
предварительный диапазон; клик фиксирует второй конец и включает все пройденные
реплики. Возврат A к исходной реплике снова показывает исходное anchor-слово.
Подсказка «Выберите второе слово» сама является кнопкой отмены при hover/click;
Esc делает то же.

## Словарь и offline sync

Новая пользовательская база не принадлежит `library.db`. Источник правды и
offline-проекция разделены намеренно:

```text
YouTube / Словарь / Карточки / Практика
  → extension IndexedDB: entries + outbox + meta
  → /vocabulary/sync в SC Desktop
  → bearer API Voice Record
  → canonical vocabulary + FSRS
```

IndexedDB открывает словарь, карточки и статусы без сети. Мутации помечаются
dirty, review-операции складываются в outbox и повторяются после восстановления
Voice Record. Ручные переводы двух клиентов не затираются молча: конфликт
остаётся видимым до выбора версии.

Identity слова — `lemma + part of speech + source/target language`. Наблюдаемые
инфлексии одной лексемы объединяются, но омонимы разных частей речи остаются
разными карточками. Быстрый локальный анализ нужен для мгновенного UI; словарь и
контекстное AI-объяснение могут уточнить lemma/POS и безопасно перенести запись.

Статус `saved | known` проецируется на каждую видимую форму слова. В английской
строке используется canonical/form match, в русской — Azure alignment с точным
dictionary fallback. Активная подсветка клика не заменяет постоянный статус.

`library.db` сохраняет другую ответственность:

- `translation_cache` — provider response по ключу
  `(operation, source language, target language, source text)`;
- `learning_entries` / `learning_examples` — legacy-источник однократной
  миграции старых сохранений, не текущая canonical vocabulary.

Отдельная options-страница расширения содержит Словарь, бесконечные Карточки,
Практику и Настройки. Текущая практика сохраняется в `meta` IndexedDB отдельно
от vocabulary entries; она не меняет FSRS без явного ответа карточки.

## Настройки

Источник правды после bootstrap — общий `~/.config/sc/settings.json`, секция
`browser_extension.youtube`, schema version 2. Настройки меняются как из
SC Desktop (`Настройки → YouTube`), так и из компактной панели в плеере. Открытая
YouTube-вкладка перечитывает desktop-настройки и применяет их без F5.

Поля learning-слоя:

- `learning_enabled`;
- `learning_target_lang`;
- `learning_auto_pause`;
- `learning_subtitle_position` (`top | bottom`);
- `learning_controls_mirrored`;
- `learning_translation_mode` (`hover | always`);
- `learning_hide_native_subtitles`;
- `learning_subtitle_offset_x` / `learning_subtitle_offset_y`;
- `learning_ai_explanation`;
- `learning_card_autoplay`.

## Проверка

Проверенный сценарий на `youtube.com/watch`:

1. CC on/off соответственно включает и полностью снимает SC-слой.
2. Дорожка `en/asr` получена локальным fallback: 722 timed cues; повторный вызов
   вернул `cached: true`.
3. Azure перевёл реплику и dictionary lookup вернул несколько вариантов слова.
4. Предыдущая/повтор/следующая реплика меняют позицию видео; повтор сохраняет
   текущую cue.
5. Автопауза остановила видео у конца реплики и была возвращена в исходное
   выключенное состояние.
6. Смена сторон переставила control rails и была возвращена обратно.
7. Словарь Voice Record вернул 29 active entries; extension sync восстановил
   их в IndexedDB без ручного входа.
8. Изменение автопаузы в SC Desktop дошло до уже открытой YouTube-вкладки и
   после проверки было отменено.
9. `auxiliary` сохранил статус в английском и aligned-русском тексте;
   `measure`-глагол не подсветил `a measure`-существительное.
10. A/D прошли из cue 130 в cue 131 и обратно с сохранённым anchor; итоговая
    фраза включила обе реплики, click по hint полностью отменил диапазон.
11. Открытие/закрытие word-card не изменило top/left/height subtitle-card;
    `short-term` дал один DOM-token и одну карточку.
12. Отдельная вкладка Практика прошла start/turn, reload, словарный popover,
    Azure-переводчик, duplicate-click guard и видимую error-деградацию. Полный
    контракт — `fact-разговорная-практика.md`.
