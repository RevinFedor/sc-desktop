# Разговорная практика по личному словарю

Вкладка **Практика** живёт на отдельной React-странице расширения рядом со
словарём и карточками. Это намеренно не микрофонный клиент и не ещё один общий
AI-чат: пользователь отвечает в обычном английском `textarea`, поэтому может
печатать или использовать системную диктовку Voice Record без дублирования
Soniox, разрешений на микрофон и логики завершения записи в браузере.

## Пользовательский контракт

1. `Начать` выбирает до 12 актуальных сохранённых слов и открывает один связный
   диалог.
2. AI пишет короткую английскую реплику и её русский перевод. В одну реплику
   естественно попадают 1–3 слова из набора, а не весь словарь сразу.
3. Слова из словаря постоянно выделены. Клик по любому английскому слову
   открывает локальную карточку с переводами и состояниями `Знаю` / `В словарь`.
4. Пользователь отвечает по-английски. После отправки AI кратко объясняет
   существенную ошибку, при необходимости показывает естественный исправленный
   вариант и продолжает тот же разговор.
5. Справа доступен самостоятельный переводчик `ru ↔ en`: результат можно
   скопировать или вставить в composer. Вставка возвращает фокус в поле ответа.
6. `Новый диалог` явно сбрасывает текущую сессию; простой reload её восстанавливает.

Первый ход — уже диалог, а не отдельное упражнение «переведи русское предложение».
Смешивать эти режимы в одном сообщении не нужно: разговор оценивает способность
ответить по смыслу, тогда как перевод предложения требует другого критерия
правильности.

## Цепочка владельцев

```text
React-страница расширения
  ├─ offline vocabulary + текущая сессия → extension IndexedDB
  ├─ /translator/* → SC Desktop → Azure Translator
  └─ /learning/practice → SC Desktop
         → authenticated local Voice Record API
         → Gemini Flash-Lite без tools
```

Расширение не получает Azure/Gemini/Soniox keys. SC Desktop владеет Azure и
обнаружением локального Voice Record; Voice Record владеет Gemini key и
каноническим словарём. Изменение одного провайдера не требует переносить секреты
или серверную модель в браузер.

## Набор слов и identity

В практику берутся только активные записи `state=saved`, `kind=word`. Порядок
наследует приоритет карточек: новые и забытые формы оказываются раньше. Сессия
запоминает stable vocabulary keys, а не отображаемые строки.

Подсветка строится по той же канонической identity, что YouTube-слой: lemma +
part of speech + language pair. Наблюдаемые формы и безопасно сгенерированные
инфлексии одной лексемы подсвечиваются вместе; омонимы разных частей речи не
склеиваются. Поэтому сохранённый `measure`-глагол не делает изученным
`a measure`-существительное.

## Practice-turn, а не общий agent-chat

Запрос ограничен одним JSON-turn и не создаёт запись в `conversations.json`:

```json
{
  "action": "start | turn",
  "answer": "English answer",
  "vocabulary": [{ "id": "stable key", "term": "reliable" }],
  "history": [{ "role": "assistant", "english": "...", "russian": "..." }]
}
```

Ответ также структурирован: `feedbackRussian`, `correctedEnglish`,
`assistantEnglish`, `assistantRussian`, `usedVocabularyIds`. История ограничена
последними ходами, vocabulary — 16 записями на серверной границе. Модель не может
вернуть произвольный id: сервер оставляет только идентификаторы из входного набора.

Здесь намеренно используется одиночный `geminiSend` с Flash-Lite, а не
`runAgent`. Полный агент добавил бы MCP/bash/file tools, общий системный prompt,
confirm-flow и историю обычного AI-чата — побочные эффекты, которых нет в учебной
реплике. Правило Voice Record «каждое сообщение чата идёт через agent-loop» не
нарушено: practice-turn не является сообщением общего чата.

## Переводы и словарная карточка

Русский текст AI-реплики возвращается в том же structured turn, чтобы пара не
расходилась по смыслу. Перевод собственного английского ответа и боковой
переводчик используют Azure через существующий SC bridge.

Словарная карточка открывается сразу, до сети. Сохранённый перевод и состояние
берутся из IndexedDB; варианты Azure заполняют карточку асинхронно. Изменение
`Знаю` / `В словарь` проходит через тот же offline outbox и последующую
синхронизацию с Voice Record, а не через отдельный practice-store.

## Локальная сессия и деградация

Текущий диалог хранится отдельно от карточек в metadata той же IndexedDB. В нём
лежат только bounded bilingual messages и ссылки на vocabulary keys. Reload
восстанавливает диалог; `Новый диалог` удаляет его явно.

Offline остаются доступны история, словарные статусы и уже полученные переводы.
Новый AI-turn требует запущенного Voice Record и сети; Azure-перевод требует SC
Desktop. Ошибка не добавляет ложное assistant-message: исходный ответ возвращается
в composer, а рядом показывается причина. Синхронный busy-guard блокирует второй
запрос даже при двух click-событиях до React-render.

Разговорная практика сама не вызывает FSRS `review`: употребление слова в
сгенерированной реплике не доказывает, что пользователь его вспомнил. Расписание
меняется только через явные ответы карточек.

## Подтверждённая проверка

- production Voice Record и SC Desktop вернули реальные `start` и `turn` через
  Gemini 3.1 Flash-Lite; turn содержал русскую обратную связь, исправление и
  следующую двуязычную реплику;
- UI проверен на start/send, словарной карточке, Azure-переводчике, вставке в
  composer, reload-восстановлении, двойной отправке и серверной ошибке;
- при двойном click получен один turn; при ошибке количество сообщений не
  изменилось, а текст вернулся в composer;
- общий словарь в проверенном запуске содержал 29 активных записей.
