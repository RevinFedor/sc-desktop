# Knowledge: Avito через browser MCP

Avito-инструменты живут в **browser MCP** (`mcp/browser/index.js` + handlers в
`browser-extension/mcp-handlers.js`) и работают через реальный браузерный профиль
пользователя: cookies, подписка, скрытые/забронированные объявления, авторизация
и мини-мессенджер доступны так же, как при ручном открытии Avito.

Первый use-case: пользователь один раз собирает Avito search URL с нужными
фильтрами (город, комнаты, собственники, секретные/забронированные объявления,
цена, карта), а AI дальше в фоне собирает выдачу, открывает карточки, читает
условия/фото/описание/дом и возвращает кандидатов **с прямыми ссылками на
объявления**.

Второй use-case: обычные товары (например MacBook). Для простых товарных поисков
`avito_search` умеет сам собрать URL из `query/q/search`, `city/region`,
`category/category_path`, `price_min/price_max` и `seller_type`:

- `seller_type:"private"` / `person` / `owner` → `user=1`;
- `seller_type:"company"` / `business` / `shop` → `user=2`;
- `category:"noutbuki"` / `laptops` / `ноутбуки` → `/noutbuki`.

Для сложных фильтров по-прежнему лучше передавать готовый Avito URL: `f=...` и
часть категорийных фильтров остаются opaque-состоянием Avito.

## Инструменты

- `avito_search` — читает выдачу, пагинирует, дедупит по item id и возвращает
  cards: title, URL, цена, адрес/метро, описание, первые фото; для недвижимости
  дополнительно комнаты/площадь/этаж и snippets условий. `detail_limit` открывает
  первые N карточек и прикладывает detail-данные.
- `avito_item_detail` — открывает конкретное объявление и вытаскивает полный
  detail: адрес/метро, секции параметров (`О квартире`, `Характеристики`,
  `О ноутбуке` и т.п.), описание, фото, продавца, ссылки на дом/отзывы если есть
  и preview мини-чата. `seller` нормализуется как `{name, kind, rating,
  review_count, profile_url, raw}`, где `kind` = `private`/`company`/`landlord`/
  `owner` когда Avito показывает этот тип.
- `avito_messages_list` — открывает вкладку «Сообщения» (`/profile/messenger`)
  в фоне и читает список диалогов: `channel_id`, URL, продавец/контакт, товар,
  цена, последнее сообщение, время, `unread`, теги (`Ждёт ответа`) и общий
  счётчик непрочитанных. С `query:"macbook"` по умолчанию заполняет авитовский
  поиск по сообщениям и возвращает найденные каналы; `unread_only:true` оставляет
  только непрочитанные. Это безопасный режим для проверки unread, потому что он
  не открывает отдельные треды.
- `avito_thread_read` — открывает конкретный `/profile/messenger/channel/...` и
  читает сообщения: направление (`incoming`/`outgoing`), текст, время, read-marker,
  наличие границы `Непрочитанные сообщения`, состояние composer и suggested replies.
  Важно: само открытие непрочитанного треда на Avito может пометить его прочитанным.
- `avito_chat_read` — открывает мини-мессенджер и читает текущий thread/composer.
- `avito_message_draft` — заполняет textarea, но не отправляет.
- `avito_message_send` — отправляет только при `confirm:true`. Без confirm handler
  возвращает ошибку **до** открытия/заполнения textarea (`drafted:false`), чтобы
  случайный вызов не менял черновик.

Сигнатуры MCP-tool в `mcp/browser/index.js` обновляются только после перезапуска
MCP-сессии. Логика расширения (`mcp-handlers.js`) hot-reload'ится через extension
reload; новые action'ы можно тестировать до рестарта через `batch` с raw
`mcp_avito_*`.

## Фоновая вкладка и защита active tab

Avito tools по умолчанию должны работать **только по `url` в собственной фоновой
вкладке**. Текущая вкладка пользователя не является implicit input. Если надо
прочитать уже открытую Avito-вкладку, передаётся явный `tabId`; для raw `batch`
добавлен флаг `__implicitTabId`, потому что batch технически подставляет active
tabId в подкоманды. Такой tabId **не считается разрешением** трогать текущую
вкладку; явное разрешение — только реальный `tabId` в конкретной sub-action или
`use_current_tab:true`.

Почему так жёстко: при разработке Avito search по URL внутри `batch` подхватил
active tabId, навигировал текущую вкладку пользователя на Avito и выглядел как
«фоновый» вызов только снаружи. Защита теперь трёхслойная:

1. `url` обязателен, если нет явного tabId.
2. Перед фоновой работой handler запоминает active tab/window.
3. После `tabs.create`/`tabs.update`/`tabs.remove` вызывается restore active tab;
   если workTabId совпал с сохранённой active-вкладкой, handler отказывается
   навигировать её.

Это важнее удобства: цена ошибки — увести или закрыть вкладку, где пользователь
прямо сейчас работает или смотрит контент.

Restore active tab не должен фокусить окно браузера на уровне macOS. Достаточно
`chrome.tabs.update(tabId, {active:true})`: это возвращает выбранную вкладку внутри
Яндекс Браузера, но не вытаскивает сам Яндекс поверх Custom Terminal. Не добавлять
сюда `chrome.windows.update(windowId, {focused:true})` — фоновый `batch`/search
начнёт красть фокус у текущего приложения.

Restore target не является вечным snapshot'ом. Если job стартовал с вкладки 1,
создал/обновляет служебную вкладку 3, а пользователь за это время руками перешёл
на вкладку 2, следующие `tabs.update` служебной вкладки должны сохранять уже
вкладку 2. Поэтому перед каждой навигацией work-tab handler перечитывает текущую
active tab и обновляет restore target, если active tab не является самой work-tab.
Иначе симптом выглядит так: «я работаю во второй вкладке, третья MCP-вкладка
обновляется, и меня снова перекидывает на первую».

## Search URL как источник фильтров

Надёжный режим — передавать готовый Avito URL, который пользователь собрал руками.
Avito кодирует часть фильтров в `f=...`, часть оставляет query-параметрами:
`user=1` для собственников, `localPriority`, `map=...` для области карты,
`p=N` для страниц. MCP не пытается расшифровывать все значения `f` в человеко-
читаемый конфиг: это opaque state Avito, его лучше сохранять и переиспользовать.

`map=` — base64 JSON вида `{searchArea:{latBottom,latTop,lonLeft,lonRight},zoom}`.
Handler умеет собрать его из `map_bbox`, но это не полноценная гарантия выдачи:
на живом Avito map bbox вокруг Сокольников с тем же `f` вернул 0 DOM-карточек,
хотя обычная выдача с похожими фильтрами существовала. Поэтому map bbox — useful
hint, не единственный source of truth.

Текстовый `q=Сокольники` тоже нельзя считать геофильтром. Avito ранжирует по
релевантности текста и может вернуть Белорусскую, Ясенево, Митино и другие
нерелевантные районы в первых карточках. После search обязательно пост-фильтровать
по `detail.address`, `detail.address.metros`, описанию и фактическому району.

## Как ранжировать квартиры

Для ответа пользователю важнее не «вся выдача», а короткая подборка со ссылками.
Минимальный формат результата:

- прямая Avito-ссылка;
- цена, площадь, комнаты, этаж;
- метро/адрес и насколько это реально подходит к зоне поиска;
- залог/комиссия/ЖКУ, собственник или нет;
- ремонт по секции «О квартире» и по первым фото: современный, аккуратный старый,
  косметический, «бабушкин» и т.п.;
- риски: старый дом, мало отзывов дома, запрет животных/детей/курения, короткий
  срок, высокая цена относительно цели.

Окружение оценивается объективными прокси, а не демографическими ярлыками:
парки и зелёные зоны, шумные магистрали, расстояние до метро/МЦК/автобуса,
рейтинги и отзывы домов, Яндекс.Карты по ТЦ/супермаркетам/кафе, наличие
нормальных повседневных магазинов рядом. Для запроса «приятный район / хорошие ТЦ»
проверять через `yandex_maps_search`: категории, rating.score/reviews/votes,
сайты, адреса и набор магазинов/кафе. Пример живой проверки: вокруг
Охотничьей/Сокольников нашлись ТЦ «Сокольники» 4.6, Перекрёсток 24/7, ВкусВилл,
Караваевы и несколько кафе/ресторанов с большим числом отзывов — это сильнее,
чем просто «есть ТЦ».

## Chat safety

Чтение списка, чтение треда и отправка сообщений — разные режимы.
`avito_messages_list` можно вызывать для проверки последних/непрочитанных диалогов
и поиска по теме (`query:"ноутбук"`) без входа в тред. `avito_thread_read` уже
открывает конкретный канал и может сбросить unread на стороне Avito — использовать
его только когда пользователь действительно просит прочитать диалог.
`avito_chat_read` можно вызывать для проверки мини-чата на странице объявления.
`avito_message_draft` допустим только когда пользователь реально просит подготовить
текст. `avito_message_send` требует `confirm:true`; в тестах и подборе квартир без
явной команды пользователя сообщения не отправлять.

Если `url` передан без `tabId`, chat actions создают фоновую вкладку и по умолчанию
держат её открытой, чтобы можно было визуально проверить черновик/диалог. Для
чистого read-only скана передавать `keep_open:false`.
